4. Quote form privacy, delivery and accessibility
Forms explicitly POST to /api/quote. The API accepts JSON, URL-encoded and multipart bodies, validates with Zod and the honeypot, checks origin, and limits streamed input bytes. HTML fallbacks redirect with HTTP 303 to /quote-result/?state=success or state=error; no form values are included in URLs. The result route is noindex and excluded from sitemap.
Client submissions have a synchronous pending guard, disabled pending/success submit control, accessible status/alert feedback and focus management. Hidden per-form tokens plus a bounded ten-minute per-instance delivery guard prevent concurrent/replayed delivery in one server instance. An Idempotency-Key is forwarded to the delivery provider. Cross-instance/restart deduplication requires provider support or durable storage; this implementation does not claim that guarantee.
The honeypot is positioned off-screen, aria-hidden and removed from tab order, with autocomplete off and no announced label. A successful acknowledged JS submission pushes one generate_lead event per token to dataLayer, containing only event and form identifiers. Failed or invalid submissions do not emit conversion events. No analytics provider, credentials or personal event parameters were added.
